Learning Journal: My First Experience with GitHub Pages

Date: September 30, 2026
 Topic: GitHub Pages
 Learning Level: Beginner

What I wanted to learn

Today, I explored GitHub Pages for the first time. My objective was to understand what GitHub Pages is, how it relates to a GitHub repository, and how I can use it to publish content as a website.

What I learned

I learned that GitHub Pages provides a way to publish a static website directly from a GitHub repository. It can be used for purposes such as project documentation, blogs, portfolios, or simple websites. GitHub's official quickstart demonstrates creating a repository, enabling Pages under repository settings, selecting a publishing source, and then accessing the published website.

One concept that became clearer to me was the relationship between the repository and the website:

GitHub Repository → Source Content → GitHub Pages → Published Website

The repository contains the source files, while GitHub Pages takes the configured content and publishes it as a website.

I also learned that GitHub Pages recognizes files such as index.html, index.md, or README.md as entry files depending on the publishing configuration.

My first hands-on understanding

The basic workflow I learned was:

Create or select a GitHub repository.
Add the content that I want to publish.
Open the repository's Settings.
Navigate to Pages.
Select the publishing source.
Select the appropriate branch when using branch-based deployment.
Save the configuration.
Access the published GitHub Pages site.

GitHub also supports deployment through GitHub Actions, so branch-based publishing is not the only deployment approach.

What was interesting to me

The most interesting part was realizing that GitHub is not limited to storing source code and managing issues or projects. The content maintained in a repository can become an accessible website.

Given that I already use GitHub for project and program-management activities, I can see GitHub Pages being particularly useful for:

Project documentation
Technical guides
Team knowledge pages
Architecture or engineering documentation
Release information
Learning notes

These are potential use cases I identified for myself rather than requirements from GitHub.

Reflection

Before learning GitHub Pages, I primarily thought about GitHub in terms of repositories, issues, projects, branches, pull requests, and Actions.

My key takeaway today is:

A GitHub repository does not have to remain just a collection of files. With GitHub Pages, it can also become the source for a published website.

For my next learning session, I would like to create a small Markdown-based site and explore how changes move through this flow:

Edit → Commit → Build/Deploy → Published Page
